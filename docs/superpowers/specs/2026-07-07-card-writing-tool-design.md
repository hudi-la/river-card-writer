# 卡片式写作工具 · 设计文档

*日期：2026-07-07　·　状态：设计定稿，待写实现计划*

## 0. 一句话

一个给作者自己用的、卡片式的书籍写作工具：**表面是一条可以从头读到尾的连续文字河流，底下是一串能上色、能重排、能收进盒子的软卡片**。它的唯一使命是帮作者完成写作里最难的那件事——把网状的想法压成一条线。

## 1. 缘起与定盘星

作者用 Scrivener 写书，最大的别扭是：**篇与篇之间不独立、靠"连接"长出来**，但 Scrivener 的卡片只露梗概、正文藏在背后，排顺序时看不到全部内容，无法判断"这段接那段顺不顺"。

对话中挖出的**定盘星**（压在一切设计之上）：

> 作者的脑子天生是**网状（B）**——万物互相呼应；而写作是要把这张网**压成一条线（A）**。"压成线"正是写作里最难、最费劲的劳动。
> **所以 UI 不该去讨好 B（把网画得更漂亮——那作者脑子里已经有了，画出来反而让人舒服地赖在网里）；UI 要帮的是 A。**

作者原话：**"B 是我头脑里的常态，A 是我写作的追求。我在这里希望 UI 帮助的是 A。"**

这条和作者另一个产品「阅读陪伴」同源：**不喂饭、不做捷径、帮人做难的事而不是绕过它**。这也是两个产品真正的连接点——**同一种价值观，而不是同一个界面**。

## 2. 范围

**做（第一版 = 被动的好画布）：**
- 章 / 卡片两层结构；连续河流式主视图；软卡片的切分 / 合并 / 重排。
- 颜色 = 线（主题）的连续色带。
- 手动建、命名的盒子（暂存区），及盒子 ↔ 正文的置入 / 收纳交互。
- 一小套讲究的语义段落样式 + 一个全局阅读偏好。

**明确不做（YAGNI，留数据口、以后再说）：**
- AI 帮判断/起草过渡（"轻主动信号 ②""写作伙伴 ③"）。
- 「阅读陪伴」的读书笔记流进来变卡片（消费→生产的水管）。
- 逐段自由改字体字号（属于"导出/出版"，非"写作"）。
- 手机上写作、多人协作、成书排版/导出。

## 3. 核心模型：河 + 软卡片

**表面是一条河，底下是一串有身份的卡片对象。**

- 一**章** = 一串**有序的卡片对象**。每张卡片有：id、正文、所属"线"（可空）、在章内的顺序、是否被收进某盒子。
- 渲染时把一章的卡片按序拼成**一份连续的文字文档**（河）。卡片 = 两根横线之间的一段。
- 编辑动作映射到底层对象操作：
  - **切分（下刀）** = 把一个卡片对象拆成两个。
  - **合并** = 把相邻两个对象并成一个。
  - **重排** = 把某个对象连同它的颜色搬到别处（章内或跨章）。
  - **收纳** = 把某个对象移出河流、放进盒子（仍保留身份和颜色）。

"先写成一条河、事后再下刀切卡"和"一开始就分开卡片写"只是**同一条河上的两种用法**，工具不为它们各设"模式"，也不逼作者先选。

## 4. 骨架：两层，全在左栏

左栏是唯一的导航，含**两个可折叠的组**：

- **章**：序 / 一 / 二 / …，＋新一章。点一章 → 中间显示那章的河。
- **盒子**：作者**手动新建、自己命名**的暂存区（如 素材 / 废案 / 灵感），每个前面一个小色块，＋新盒子。点一个盒子 → 中间显示那个盒子里的卡片。

**章和盒子都是"装卡片的容器"，在同一个左栏里并列，点谁开谁。** 中间是主区（河 或 盒子内容），无右栏。

## 5. 颜色 = 线（把 B 网安放成暗流）

- 每张卡片可归到一条**"线"**（主题 / 意象 / 论证 / 人物…）；线有颜色；卡片也允许**不上色**（不是每段都得归线）。
- 渲染成**连续的极淡色带**：**同一条线的相邻卡片连成一整片底色**，横线只从中穿过、**不切断颜色**；换线才换色。
- 底色淡到不打断阅读，但作者想顺某条线时扫一眼就能认出。
- 这样：**版面服务 A（线性阅读），颜色偷偷承载 B（网状）**，同屏并存不打架。作者追求的 A、脑子里的 B，一次满足。

## 6. 盒子 ↔ 正文的交互

两个方向用两套贴合各自动作的手势：

**盒子 → 正文（InDesign 置入式）**
1. 盒子里每张卡右下角有一个**小箭头图标 ⤵**（划过卡片时变亮，显"插入正文"提示）。
2. 点 ⤵ → 光标进入**"装载"态**：鼠标旁只多出一个**很小的迷你卡图标 + ＋**（不是拎着一大张卡）。
3. 回到正文、移动光标，段间出现一条**橙色落点线**指示会插在哪。
4. 点一下 → 卡片作为新的一段**正式落进河里，并从盒子移走**（移动，非复制）。Esc 卸载不插。

- 直接点盒子里的卡面 = 打开看 / 编辑这张卡（与"插入"分开，不打架）。

**正文 → 盒子（拖到目录）**
- 抓住某段正文左边的**小抓手（⠿）**拖起来，丢到左栏某个盒子上 → 收进那个盒子。

**小抓手 ⠿ 一手两用**：在河里上下拖 = 章内/跨章重排；拖到左栏盒子上 = 收纳。

**盒子的打开视图**：翻页式（一次看一张，像 gallery）和缩略图铺开，**两种都做出来试**，最终取舍留到实现时实测决定。

## 7. 排版：舒服的语义样式 + 一个全局开关

- **一小套讲究的语义段落样式**（正文 / 小标题 / 引文 / 旁注）：作者标的是"这段是什么**角色**"，工具用**统一且好看**的排版渲染。要做得舒服、有讲究，不是功能性的丑默认。
- **一个全局阅读偏好**：整份文档的阅读字体（衬线/无衬线）、字号、行宽，随时改、**统一作用**（照顾作者的眼睛，不耦合内容）。
- **不做**逐段自由改字体字号——那是"导出/出版"的事，以后再说。

理由：逐段排版会往回长出视觉噪音、是"假装在工作"的拖延面、且把内容和呈现耦死——三者都违背定盘星。

## 8. 交互默认（实测可调）

- **切分**：段间留白 hover 出现"＋在这里下刀"，或快捷键。
- **合并**：段首按退格，吃掉上面那根横线，两段并一段。
- **重排**：抓 ⠿ 上下拖，其余段让位。
- 「插入正文」图标：小箭头 ⤵，划过显文字提示。

## 9. 数据与技术

- **单独一个新 GitHub 仓库**（本地临时目录 `card-writer`，正式名待定）。
- **共享「阅读陪伴」的同一个 Supabase 项目 + 同一套登录**——"一次登录、一处数据"（作者要的"集中"），但**代码与那个可能商业化的读书产品互不拖累**。
- 交付先做**笔记本大屏网页**；将来要不要包成桌面 app（如 Electron）到时再定，不影响现在。
- 数据模型（大致）：
  - `book`：书。
  - `chapter`：属于书，有序。
  - `card`：属于书；字段含 正文、所属线(thread_id, 可空)、语义样式(role)、顺序、位置（在某章的河里 or 在某盒子里）。
  - `thread`（线）：属于书，有名字 + 颜色。
  - `box`（盒子）：属于书，有名字（可选颜色）。
- 预留但不实现的口：`card` 可来源标注（为将来"阅读陪伴笔记→卡片"的水管留位）。
